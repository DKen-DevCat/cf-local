# Phase 4c: 仕上げ

## 目的

phase-4a/4b で動作するようになった Terraform 連携 + Invalidation API を、**他人が触っても破綻しないライン**まで仕上げる。M3 達成 (= OSS β 候補) のためのフェーズ。

具体的には以下 3 軸の品質向上:

1. **API 互換性**: ResponseHeadersPolicy 対応 + AWS 互換エラー形式
2. **観測性**: HTTP request log middleware + 構造化ログ
3. **基盤の堅牢化**: inner location の unix socket 化 + stress test ベースライン取得

## スコープ

### kickoff 前相談で確定した方針

| 項目 | 決定事項 | 根拠 |
|---|---|---|
| **A-1 エラー互換レベル** | 中程度 (CloudFront `<ErrorResponse>` 形式 + 主要 Code) | AWS SDK / Terraform Provider が parse できるレベル。完全互換 (内部コード一致) は非現実的 |
| **A-2 ログフォーマット** | `log/slog` で人間可読 default + `CF_LOCAL_LOG_FORMAT=json` で JSON | dev は人間可読、CI / 観測ツール連携は JSON。両対応はほぼ無料 |
| **A-3 デバッグ UI** | 作らない (out) | ログ整備で十分。UI は OSS 公開後の v0.2 候補 |
| **D ResponseHeadersPolicy** | `CustomHeadersConfig` + `CorsConfig` のみ | ローカル開発で頻出する 2 系統に絞る。残り 3 系統 (Security / ServerTiming / RemoveHeaders) は積み |

## Phase 完了時メモ

実装中に判明した想定外 / 想定通りだった点。

### 想定外だった点

- **unix socket permission**: 公式 alpine nginx image の master=root / workers=`nginx` user 構成で `listen unix:/...` の socket file は master の umask で mode が決まり、umask 022 (default) だと workers から connect 不可で 502 になる。`reload-entrypoint.sh` で `umask 000` を設定する対処を入れた (mode 0666)。コンテナ内に nginx 以外の信頼できないプロセスは無いためリスク許容範囲。
- **isHTTPTokenName / isValidHeaderName 不一致** (review 後に修正): 4c-9 validate の `isHTTPTokenName` は RFC 7230 token char を許可、renderer の `isValidHeaderName` は `[A-Za-z0-9-]` のみ許可で、`#` 等が API を通過後 renderer で silent drop される乖離があった。/phase-review (Agent B / Agent C) で検出 → REV-2 で renderer 側の strict ルールに揃えた (silent drop より explicit エラーが UX 良)。
- **plan.md / design doc の完了マーク漏れ** (review 後に修正): tasks.md は `[x]` だが plan.md / design doc 完了条件は `[ ]` のままで CLAUDE.md §進捗の記録と乖離。/phase-review (Agent B Critical) で検出 → REV-1 で消化。

### 想定通りだった点

- **typed AWS error codes** (4c-3) は AWS SDK Go v2 v1.62.0 `deserializers.go` の smithy spec と整合し、Provider/CLI 側に regression なし
- **unix socket 化** (4c-7) は phase-2 design doc 2-2 で予告した変更を方針通り消化、bypass 経路を構造的に削除
- **slog 統合** (4c-5 / 4c-6) は CF_LOCAL_LOG_FORMAT で text/json 切替する既定路線、io.Writer ベースの reloader を logger ベースに refactor
- **policy validation 共通化** (4c-9) は phase-3 file loader が持っていた検証を AWS API path にも適用、phase-4a で「skip されていた」点を解消

### 次フェーズ (phase-4d / 4-D Lambda@Edge) への引き継ぎ事項

- 実機検証 (terraform-integration の `aws_cloudfront_response_headers_policy` E2E + vegeta baseline) は ship 時に行う前提。未実施なら次フェーズ kickoff 前に消化
