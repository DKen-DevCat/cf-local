### REV-11 (commit `c964faf`) — 実機検証で発見

- [x] **REV-11**: nginx `resolver` directive を Lambda@Edge 構成で必須化。`ngx.fetch` が host name 解決時に http (or server) context の `resolver` を要求するため、`writeConfHeader` で `hasLambdaEdge=true` のとき `resolver <addr> valid=30s ipv6=off;` を出す。`LoadResult.Resolver` / `DefaultResolver=127.0.0.11` (Docker 組み込み DNS) + `CF_LOCAL_RESOLVER` env で上書き可。リグレッションテスト 3 件追加 (default / no-bindings / custom resolver)

### REV-12 (commit `297b29e`) — 実機検証で発見

- [x] **REV-12**: forward proxy_pass を `$uri$is_args$args` に切替。`r.internalRedirect(new_uri)` 後 nginx の `$request_uri` は元クライアント値で固定で更新されないため、Lambda が viewer-request で URI を書き換えても origin に古い URI が届くバグ。`writeOuterLocationBody` に `useUpdatedURI bool` を追加し LE forward (writeForwardLocation 経由) のみ true、通常 forward (writeOuterLocation 経由) は `$request_uri` 維持 (URL encode 保持を尊重)
